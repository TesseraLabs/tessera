# Покрытие Spec9 E2E-реестром

Каждый кейс содержит стабильную квалифицированную ссылку
`requirement: spec9:<context>.<ID>`. Публичный репозиторий проверяет синтаксис
ссылки и целостность YAML-реестра, но не включает приватную продуктовую
спецификацию.

Полная проверка выполняется из приватного workspace `tessera-ws`:

```sh
npm --prefix spec9 run e2e
```

Аудит сопоставляет каждый кейс с `evidence.test` в норме и различает:

- `exact` — evidence указывает на конкретный `#case-id`;
- `coarse` — указан только файл suite;
- `missing` — ни одна норма не заявляет этот кейс как evidence;
- `invalid` — якорь ссылается на отсутствующий suite или case.

Каноническая связь двусторонняя: поле `requirement` позволяет перейти от кейса
к норме, а `evidence.test` — от нормы к исполняемой проверке. При несовпадении
ID или удалении одной стороны приватный аудит обязан завершаться ошибкой.
