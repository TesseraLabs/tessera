## MODIFIED Requirements

### Requirement: Предъявление challenge текстом для диктовки (режим 0)

Система ДОЛЖНА (MUST) поддерживать режим 0: challenge предъявляется группами, пригодными для
диктовки голосом, без QR, без URL и без обращений к сети. Номер устройства ДОЛЖЕН (MUST)
печататься с контрольным символом (ISO 7064 MOD 37,36). Режим 0 ДОЛЖЕН (MUST) работать при
полностью отсутствующей конфигурации Codes-URL.

Challenge ДОЛЖЕН (MUST) предъявляться **текстом промпта**, которым запрашивается код, а НЕ
`PAM_TEXT_INFO`: на графическом входе Astra info-сообщение до экрана не доходит, и человек,
которому нечего продиктовать, войти не может. Один канал для всех окружений — сознательный выбор
против ветвления по среде: ветка, которая исполняется только на банкомате, там же и ломается
первый раз. Основание — `fly-dm-greeter`, требование «Канал промпта как поверхность показа во
время попытки».

Идентификатор оператора НЕ ДОЛЖЕН (MUST NOT) запрашиваться первым за попытку промптом с эхом:
такой промпт греетер отвечает сам, именем из своей формы, и человек его не видит. Значение,
входящее в MAC, не может быть получено вводом, которого никто не совершал.

Метод ДОЛЖЕН (MUST) быть доступен и тогда, когда не выполнены предпосылки сертификатного
метода — не завезён якорь доверия, недоступен PKCS#11-модуль, не отвечает крипто-движок:
он существует именно для устройства, где сертификатный путь неработоспособен, и закрывать
его попыткой подготовить тот самый путь значит закрывать последнюю дверь по той причине,
ради которой она есть. Предпосылки метода кода — его собственные артефакты, их владелец
и права.

#### Scenario: Устройство без всякой серверной конфигурации
- **WHEN** на устройстве не настроен ни один Codes-URL
- **THEN** режим 0 доступен и вход по продиктованному коду проходит; режимы QR неактивны

#### Scenario: Сертификатный путь на устройстве неработоспособен
- **WHEN** самопроверка сертификатного метода не проходит — например, PKCS#11-модуль не
  загружается — а артефакты метода кода на месте
- **THEN** вход по продиктованному коду проходит; отказ сертификатного метода не
  распространяется на метод кода

#### Scenario: Вход на графическом экране Astra
- **WHEN** попытка идёт на fly-dm с темой fly-modern
- **THEN** шесть значений challenge видны инженеру в тексте промпта, вместе с полем ввода кода

#### Scenario: Идентификатор оператора не подменяется молча
- **WHEN** греетер отвечает на первый промпт с эхом именем из своей формы
- **THEN** это значение не становится `operator_id`; в MAC входит только то, что человек ввёл
  в промпт, который он видел

### Requirement: Рендер QR текстом (режим 1)

Система ДОЛЖНА (MUST) рендерить payload как UTF-8 QR через `PAM_TEXT_INFO`. Payload =
allowlisted Codes-URL + закодированный challenge (`device_id`, `nonce`, `role_id`, `level`,
`version`). QR ДОЛЖЕН (MUST) быть сканируем в моноширинном терминале (half-block, нулевой
межстрочный интервал).

Режим 1 ДОЛЖЕН (MUST) объявляться недоступным там, где `PAM_TEXT_INFO` не показывается или где
шрифт поверхности не моноширинный, — на fly-dm верно и то, и другое. Графический QR на этом
экране закрывается отдельной способностью `qr-login-overlay`, а не режимом 1.

#### Scenario: base_url вне allowlist
- **WHEN** конфигурируемый Codes-URL не в allowlist
- **THEN** метод QR не активируется (anti-phishing, fail-closed)

#### Scenario: Окружение не показывает текстовый QR
- **WHEN** попытка идёт на поверхности, где `PAM_TEXT_INFO` не виден или шрифт пропорциональный
- **THEN** режим 1 не предлагается; доступны режим 0 и, если развёрнут, графический оверлей
