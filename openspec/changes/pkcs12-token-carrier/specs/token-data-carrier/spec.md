## ADDED Requirements

### Requirement: Конверт PKCS#12 объектом данных на токене

Система ДОЛЖНА (MUST) уметь читать конверт PKCS#12 из объекта данных (`CKO_DATA`) на PKCS#11-токене: поиск по метке объекта, чтение `CKA_VALUE`, передача полученных байт в существующий разбор конверта. Носитель ДОЛЖЕН (MUST) быть равноправной альтернативой разделу USB-носителя — вся логика после получения конверта (PIN-loop, challenge-response, сборка цепи, host_binding) остаётся неизменной.

#### Scenario: Конверт прочитан с токена
- **WHEN** источником конверта задан токен и объект данных с указанной меткой найден
- **THEN** байты `CKA_VALUE` разбираются как PKCS#12 и аутентификация продолжается обычным путём

#### Scenario: Объект с указанной меткой отсутствует
- **WHEN** объект данных с заданной меткой на токене не найден
- **THEN** возвращается диагностируемая ошибка носителя — без обращения к mass-storage

### Requirement: Конверт на токене обязан быть приватным объектом

Читаться ДОЛЖНЫ (MUST) только объекты данных с `CKA_PRIVATE = true`. Объект с конвертом, доступный без аутентификации PIN-кодом, ДОЛЖЕН (MUST) отвергаться с явной диагностикой и НЕ ДОЛЖЕН (MUST NOT) использоваться молча: контейнер содержит извлекаемый приватный ключ, а инструменты по умолчанию создают объекты данных публичными.

#### Scenario: Конверт записан публичным объектом
- **WHEN** объект данных с конвертом имеет `CKA_PRIVATE = false`
- **THEN** он отвергается с диагностикой о небезопасном хранении, аутентификация не продолжается

#### Scenario: Конверт записан приватным объектом
- **WHEN** объект данных имеет `CKA_PRIVATE = true`
- **THEN** он читается после успешного логина и используется как конверт

### Requirement: Верификация записи конверта на токен

Инструмент выпуска ДОЛЖЕН (MUST) после записи объекта перечитать его и побайтово сравнить с исходником, а также ДОЛЖЕН (MUST) отказывать заранее, если размер превышает известный лимит устройства. Успешный код возврата `C_CreateObject` НЕ ЯВЛЯЕТСЯ (MUST NOT be treated as) доказательством сохранности: на Рутокен Lite запись объекта свыше ~32 КБ возвращает успех, при этом данные усекаются (48 КБ → прочитано 32768 байт) или теряются полностью (64 КБ → прочитано 0 байт).

#### Scenario: Запись усечена устройством
- **WHEN** после записи перечитанный объект не совпадает с исходником
- **THEN** операция считается неуспешной, оператор получает ошибку, объект не признаётся годным

#### Scenario: Запись подтверждена
- **WHEN** перечитанный объект побайтово совпадает с исходником
- **THEN** запись считается успешной

### Requirement: Уровень доверия носителя

Носитель на пассивном токене ДОЛЖЕН (MUST) документироваться как эквивалент «съёмный носитель плюс PIN», а НЕ как аппаратная защита ключа: приватный ключ извлекаем, подпись выполняется на хосте, `CKA_EXTRACTABLE = false` и подпись на устройстве (режим B) здесь недостижимы — пассивный токен не имеет криптографии (`C_GetMechanismList` пуст).

#### Scenario: Описание носителя в документации и материалах
- **WHEN** носитель на пассивном токене упоминается в документации, спеках или маркетинговых материалах
- **THEN** указывается извлекаемость ключа и подпись на хосте; формулировки об аппаратной защите ключа не применяются
