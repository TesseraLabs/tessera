## ADDED Requirements

### Requirement: Объекты данных

PKCS#11-слой ДОЛЖЕН (MUST) уметь искать объекты класса `CKO_DATA` по `CKA_LABEL` и читать их `CKA_VALUE`. Чтение ДОЛЖНО (MUST) выполняться после успешного логина и возвращать байты без интерпретации — разбор содержимого лежит вне слоя токена. Атрибут `CKA_PRIVATE` ДОЛЖЕН (MUST) быть доступен вызывающему коду, чтобы тот мог отвергнуть публично читаемый объект.

Слой НЕ ДОЛЖЕН (MUST NOT) считать успешный код возврата операции записи доказательством сохранности данных: провайдеры пассивных токенов усекают объект сверх лимита устройства, не сообщая об ошибке.

#### Scenario: Чтение объекта данных по метке
- **WHEN** запрошен объект `CKO_DATA` с заданной меткой и логин выполнен
- **THEN** возвращаются байты `CKA_VALUE` и значение `CKA_PRIVATE`

#### Scenario: Объект данных не найден
- **WHEN** объекта с такой меткой на токене нет
- **THEN** возвращается ошибка «объект не найден», отличимая от ошибки чтения

#### Scenario: Токен без криптографических механизмов
- **WHEN** `C_GetMechanismList` возвращает пустой список (пассивный токен)
- **THEN** работа с объектами данных остаётся доступной, а попытка использовать путь подписи на устройстве отвергается с внятной диагностикой
