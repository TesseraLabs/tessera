## MODIFIED Requirements

### Requirement: Mount живёт только в auth-фазе

`pam_sm_authenticate` ДОЛЖЕН (MUST) дропать MountGuard сразу после успешного auth (entry.rs) — USB размонтируется по завершении auth-фазы. Re-mount в session-фазе ОТСУТСТВУЕТ by design и не планируется: после auth `.p12` больше не нужен (ключ уже использован для challenge, контекст аутентификации передаётся в open_session).

Основной транспорт контекста — `pam_data`. Он ДОЛЖЕН (MUST) оставаться первым источником: вызывающий, который ведёт весь PAM-диалог в одном процессе (`fly-dm`, `login`, `sudo`), межпроцессного хранилища касаться НЕ ДОЛЖЕН (MUST NOT).

Вызывающий, разделяющий фазы по процессам, ДОЛЖЕН (MUST) поддерживаться отдельно: `pam_set_data` живёт внутри одного `pam_handle_t` и границу процесса не переживает. Для такого случая Engine ДОЛЖЕН (MUST) переносить контекст через файл, ключуемый `session_id`, который передаётся из auth-фазы в session-фазу через PAM-окружение — единственный канал, который OpenSSH переносит из auth-форка в монитор штатно.

Хранилище ДОЛЖНО (MUST) принадлежать root (`root:root 0700`, файлы `0600`) и НЕ ДОЛЖНО (MUST NOT) размещаться в каталоге, которым владеет депривилегированный пользователь демона: записанный контекст определяет MAC-метку, окружение root-хуков и аудитную личность, поэтому его подмена обязана требовать root.

Захват записи ДОЛЖЕН (MUST) быть атомарным (`rename` перед чтением), ключ ДОЛЖЕН (MUST) вычищаться из PAM-окружения сразу после потребления, а запись — исчезать по TTL средствами root. Восстановленный контекст ДОЛЖЕН (MUST) класться в `pam_data` того хендла, который его прочитал, чтобы повторный вызов `open_session` и `close_session` брали его оттуда.

Файл ДОЛЖЕН (MUST) записываться до публикации ключа в окружении; при невозможности опубликовать ключ логин ДОЛЖЕН (MUST) прерываться, а файл удаляться.

#### Scenario: Размонтирование USB после успешного auth
- **WHEN** auth-фаза завершилась успешно
- **THEN** MountGuard дропается сразу (entry.rs), USB размонтируется; `pam_sm_open_session` носитель не перемонтирует

#### Scenario: Однопроцессный вызывающий не касается межпроцессного хранилища
- **WHEN** auth- и session-фазы идут в одном процессе и `pam_data` содержит контекст
- **THEN** контекст берётся из `pam_data`, файл не читается и не создаётся

#### Scenario: Вызывающий с privilege separation открывает сессию
- **WHEN** `pam_sm_open_session` вызван в процессе, где `pam_data` пуст, а PAM-окружение несёт ключ, положенный auth-фазой
- **THEN** контекст восстанавливается из записи под этим ключом, запись захватывается атомарно и повторно не читается, ключ вычищается из окружения

#### Scenario: Ключ есть, а записи нет
- **WHEN** ключ в окружении присутствует, но записи под ним нет, она просрочена или её содержимое не разбирается
- **THEN** сессия НЕ открывается; частично восстановленный контекст не используется
