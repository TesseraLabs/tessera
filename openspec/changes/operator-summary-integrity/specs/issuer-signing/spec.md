## ADDED Requirements

### Requirement: Неподделываемость сводки операции

Сводка операции, показываемая оператору перед подписью, ДОЛЖНА (MUST)
отображать содержимое TBS так, чтобы никакое значение из него не могло скрыть,
оборвать или подделать её строки. Значения `subject`, ролей, хостов и тегов
приходят из TBS и не ограничены ничем, кроме валидности UTF-8, поэтому
управляющие символы C0 (`U+0000`..`U+001F`), C1 (`U+0080`..`U+009F`), `DEL`
(`U+007F`) и разделители строк `U+2028`/`U+2029` НЕ ДОЛЖНЫ (MUST NOT)
достигать операторской поверхности в активном виде: каждый такой символ
заменяется видимым маркером вида `\uXXXX` наравне с bidi-контролями. Переносы
строк в сводке принадлежат рендереру и НЕ ДОЛЖНЫ (MUST NOT) порождаться
значением.

Нейтрализация касается только отображения: разобранная структура сводки и
подписываемые байты остаются нетронутыми, поэтому показанное и подписанное
описывают одни и те же данные.

#### Scenario: NUL в значении не обрывает диалог
- **WHEN** значение роли или хоста содержит кодовую точку `U+0000`, а сводка отображается через pinentry
- **THEN** оператор видит на её месте маркер `\u0000` и все последующие строки сводки целиком

#### Scenario: Перенос строки не подделывает строку сводки
- **WHEN** значение содержит `U+000A` либо `U+2028`, оформленный как ещё одна пара «подпись: значение»
- **THEN** перенос отображается маркером, и число строк сводки определяется только рендерером

#### Scenario: Обычные значения не искажаются
- **WHEN** значения содержат кириллицу, латиницу, цифры и знаки препинания без управляющих символов
- **THEN** сводка воспроизводит их байт-в-байт, как и до нейтрализации

#### Scenario: Маркер нейтрализации строится только из шестнадцатеричных цифр
- **WHEN** нейтрализуется любой символ из закрытого множества выше
- **THEN** маркер состоит из `\u` и четырёх цифр `0..9A..F`, и ни при каком входе не содержит символа, который сам подлежит нейтрализации
