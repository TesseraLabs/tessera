## ADDED Requirements

### Requirement: Сборка контейнера PKCS#12

Инструмент выпуска ДОЛЖЕН (MUST) уметь собирать контейнер PKCS#12 из закрытого ключа,
выпущенного сертификата и цепочки доверия. Собранный контейнер ДОЛЖЕН (MUST) читаться
существующим путём проверки на устройстве без изменений в агенте.

Раскладка содержимого ДОЛЖНА (MUST) быть такой:

- закрытый ключ — в зашифрованной части, под паролем контейнера;
- **сертификат листа — в незашифрованной части**: от этого зависит диагностика на экране
  входа, отличающая «не тот носитель» от «неверный PIN»
  (см. [usb-media-pkcs12](../../../../specs/usb-media-pkcs12/spec.md));
- промежуточные сертификаты цепочки — в контейнере либо отдельным файлом цепочки.

Алгоритмы защиты ДОЛЖНЫ (MUST) выбираться из числа принимаемых проверкой на устройстве;
устаревшие схемы, недоступные в современных сборках OpenSSL без включения legacy-провайдера,
применяться НЕ ДОЛЖНЫ (MUST NOT).

Собранный контейнер ДОЛЖЕН (MUST) быть прочитан обратно тем же кодом разбора до выдачи
оператору: успешный результат сборки не является доказательством пригодности артефакта.

#### Scenario: Контейнер читается проверкой на устройстве
- **WHEN** контейнер собран штатной операцией
- **THEN** он разбирается кодом проверки: ключ извлекается по паролю, сертификат — без пароля

#### Scenario: Самопроверка после сборки
- **WHEN** сборка завершена
- **THEN** контейнер перечитывается и сверяется с исходными ключом и сертификатом; при расхождении артефакт не выдаётся, операция помечается ошибкой

#### Scenario: Сертификат в зашифрованной части
- **WHEN** запрошена сборка, при которой сертификат попал бы в зашифрованную часть
- **THEN** операция отвергается: такой контейнер лишает вход диагностики, отличающей неверный носитель от неверного PIN

### Requirement: Пароль контейнера

Пароль контейнера ДОЛЖЕН (MUST) по умолчанию порождаться самим инструментом из системного
источника случайности и показываться оператору один раз, с указанием, что повторно он не
восстанавливается. Пароль, заданный оператором, ДОЛЖЕН (MUST) приниматься, но проверяться на
минимальную длину; пароль НЕ ДОЛЖЕН (MUST NOT) приниматься значением аргумента командной
строки.

Пароль НЕ ДОЛЖЕН (MUST NOT) попадать в журнал выпусков, логи, имена файлов и аргументы
процессов; в памяти он ДОЛЖЕН (MUST) жить в затираемом виде.

Инструмент НЕ ДОЛЖЕН (MUST NOT) записывать пароль рядом с контейнером: контейнер и пароль
доставляются разными каналами (см. [issuance-workflows](../../../issuance-workflows/specs/issuance-workflows/spec.md)),
и файл с паролем на том же носителе уничтожает это разделение.

#### Scenario: Пароль по умолчанию
- **WHEN** оператор не задал пароль
- **THEN** пароль порождается инструментом, показывается один раз и не сохраняется ни в каком файле

#### Scenario: Попытка сохранить пароль на носитель
- **WHEN** запрошена запись пароля рядом с контейнером
- **THEN** операция отвергается с указанием требования о разных каналах доставки

#### Scenario: Пароль в аргументах
- **WHEN** ищется способ передать пароль неинтерактивно
- **THEN** доступны только поток ввода или файл; флага, принимающего пароль значением, не существует

### Requirement: Раскладка носителя

Инструмент ДОЛЖЕН (MUST) уметь размещать собранные артефакты на носителе так, как их ищет
проверка на устройстве: контейнер по пути `certs/user.p12` (либо по пути, заданному
конфигурацией устройства), цепочка — `certs/chain.pem`. Каталоги, которых нет, ДОЛЖНЫ (MUST)
создаваться.

Перед перезаписью существующего контейнера ДОЛЖНО (MUST) запрашиваться подтверждение: на
носителе может лежать действующее удостоверение другого инженера.

Раскладка на пассивный токен выполняется правилами
[token-data-carrier](../../../pkcs12-token-carrier/specs/token-data-carrier/spec.md), включая
обязательную верификацию записи чтением; настоящее требование её не дублирует.

#### Scenario: Подготовка флешки
- **WHEN** оператор указывает смонтированный носитель как цель раскладки
- **THEN** контейнер и цепочка оказываются по путям, которые ищет проверка на устройстве; вход не требует правки конфигурации

#### Scenario: На носителе уже есть контейнер
- **WHEN** по целевому пути уже лежит контейнер
- **THEN** перезапись выполняется только после явного подтверждения
