## ADDED Requirements

### Requirement: Ключ листа, сгенерированный инструментом

Ядро ДОЛЖНО (MUST) поддерживать третий источник ключа листа наряду с открытым ключом и запросом
на сертификат: ключевую пару, сгенерированную самим инструментом в момент выпуска. Такой выпуск
ДОЛЖЕН (MUST) проходить те же проверки, что и остальные источники, — состав расширений,
монотонность рамок, пригодность рамок, самопроверка результата.

Генерация ДОЛЖНА (MUST) выполняться из криптографического источника случайности платформы.
Допустимые типы ключей ДОЛЖНЫ (MUST) ограничиваться теми, которые принимает проверка на
устройстве; тип, для которого проверка подписи не реализована, НЕ ДОЛЖЕН (MUST NOT) предлагаться
как выбор — иначе выпуск формально успешен, а результат непригоден.

Закрытый ключ ДОЛЖЕН (MUST) существовать только в памяти процесса и в итоговом контейнере.
Инструмент НЕ ДОЛЖЕН (MUST NOT) записывать его отдельным файлом, во временный файл или в
стандартный вывод, и ДОЛЖЕН (MUST) затирать его буферы после сборки контейнера.

Факт того, что ключ порождён выпускающим, ДОЛЖЕН (MUST) фиксироваться в журнале выпусков: он
меняет свойства выданного удостоверения — закрытый ключ известен не только инженеру.

#### Scenario: Выпуск с генерацией ключа
- **WHEN** оператор запрашивает выпуск листа без открытого ключа и без запроса на сертификат
- **THEN** ключевая пара порождается инструментом, лист выпускается со скоупом, заданным оператором, и собирается контейнер

#### Scenario: Тип ключа без поддержки проверки
- **WHEN** запрошен тип ключа, для которого проверка подписи на устройстве не реализована
- **THEN** выпуск отвергается до генерации, с указанием поддерживаемых типов

#### Scenario: Закрытый ключ не попадает на диск отдельно
- **WHEN** выпуск с генерацией ключа завершился успехом или ошибкой
- **THEN** ни одного файла с закрытым ключом, кроме итогового контейнера, не создано; буферы затёрты

#### Scenario: Происхождение ключа в журнале
- **WHEN** удостоверение выпущено с генерацией ключа инструментом
- **THEN** запись журнала позволяет отличить такую выдачу от выдачи по запросу инженера
