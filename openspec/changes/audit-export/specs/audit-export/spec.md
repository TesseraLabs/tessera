# audit-export — вывоз аудита с офлайн-устройства

## ADDED Requirements

### Requirement: Срез журнала в кодировке «анкер и нагрузки»
Срез ДОЛЖЕН (MUST) содержать полный хвост цепочки с последнего вывезенного `seq` и
кодироваться как анкер (заверенная голова с полным контекстом) плюс полезные нагрузки
записей без повторения `seq` и `prev_hash`. Верификатор ДОЛЖЕН (MUST) пересобирать
опущенные поля от анкера и получать тот же результат проверки, что по полному журналу.
Формат среза ДОЛЖЕН (MUST) быть закреплён голден-тестами сериализации — иначе кодировка
разъедется между версиями устройства и инструмента приёма, а вывезенное перестанет
верифицироваться.

#### Scenario: Верификация вывезенного среза
- **WHEN** владелец проверяет срез, снятый с устройства
- **THEN** цепочка пересобирается от анкера и проверяется полностью; подмена любой нагрузки
  обнаруживается

#### Scenario: Пропущенный рейс
- **WHEN** вывоз не выполнялся несколько периодов
- **THEN** следующий срез содержит весь хвост с последнего вывезенного `seq`, а не только
  свежие записи

### Requirement: Сверочная проекция входов
Срез ДОЛЖЕН (MUST) включать проекцию входов для сверки с квитанциями операторов: nonce,
время, роль, уровень, исход, номер билета. Проекция сама по себе НЕ ДОЛЖНА (MUST NOT)
считаться доказательством: она ДОЛЖНА (MUST) быть включена в цепочку аннотацией либо
сопровождаться анкером. Вывоз проекции без анкера ЗАПРЕЩЁН (MUST NOT).

#### Scenario: Сверка с квитанциями операторов
- **WHEN** владелец сопоставляет проекции устройств с квитанциями кабинетов за период
- **THEN** видны обе стороны расхождений: входы без квитанций и квитанции без входов

#### Scenario: Попытка вывезти только проекцию
- **WHEN** запрошен срез, состоящий из одной проекции без анкера
- **THEN** операция отклоняется — такой срез не доказывает полноту

### Requirement: Агрегированные срезы запрещены
Срез НЕ ДОЛЖЕН (MUST NOT) заменять записи сводками и агрегатами: в агрегате пропущенная
запись неотличима от удалённой, и tamper-evidence теряется. Сжатие содержимого допустимо,
агрегация содержимого — нет.

#### Scenario: Запрос сводки вместо записей
- **WHEN** оператор запрашивает «только итоги за месяц» вместо записей
- **THEN** инструмент такой срез не производит; итоги считаются на стороне приёма из
  верифицированных записей

### Requirement: Запись среза на носитель
Срез ДОЛЖЕН (MUST) записываться и на примонтированный носитель, и в PKCS#11 data-объекты
токена. Перед записью ДОЛЖЕН (MUST) проверяться бюджет носителя собственной арифметикой;
после записи — верификация чтением. Срез НЕ ДОЛЖЕН (MUST NOT) считаться вывезенным до
успешной верификации, и `seq` последнего вывезенного при неуспехе НЕ ДОЛЖЕН (MUST NOT)
продвигаться.

#### Scenario: Носитель заполнен
- **WHEN** свободной памяти носителя не хватает под срез
- **THEN** операция отказывает до начала записи с указанием нехватки; частичного среза
  не появляется

#### Scenario: Молчаливое обрезание при записи
- **WHEN** носитель принял запись «успешно», но объект обрезан
- **THEN** контрольное чтение выявляет расхождение, срез не считается вывезенным,
  указатель последнего вывезенного `seq` не продвигается

### Requirement: Учёт вывезенного
Устройство ДОЛЖНО (MUST) хранить `seq` последнего успешно вывезенного среза. Повторный
вывоз того же диапазона ДОЛЖЕН (MUST) быть возможен и идемпотентен (потерянный носитель),
и НЕ ДОЛЖЕН (MUST NOT) стирать записи из журнала: удаление вывезенного — отдельная
операция под политикой хранения.

#### Scenario: Потерянный носитель
- **WHEN** носитель со срезом утерян и требуется повторный вывоз того же диапазона
- **THEN** срез снимается повторно тем же содержимым; журнал не пострадал
