# build-release Delta Specification

## ADDED Requirements

### Requirement: Регрессионный прогон на живой системе

Поведение установленной системы ДОЛЖНО (MUST) покрываться реестром e2e-кейсов и прогоняться
раннером `cargo xtask e2e` вне CI — в контейнерном профиле или на VM (capability
`e2e-harness`). Покрытию подлежат раскладка пакета, PAM-фазы на живом стеке, обнаружение
носителя, отзыв, enforcement и выпуск. Результат ДОЛЖЕН (MUST) сверяться с
`tests/e2e/BASELINE.md`.

Перед выпуском релиза ДОЛЖЕН (MUST) выполняться полный прогон реестра во всех доступных
профилях; расхождения с baseline ДОЛЖНЫ (MUST) быть разобраны и либо устранены, либо
осознанно зафиксированы обновлением baseline. Прогон, содержащий `ERROR` или провал
teardown, evidence релиза НЕ ДАЁТ (MUST NOT).

Требование дополняет, но не заменяет «Тестовое покрытие (evidence)»: unit- и
интеграционные тесты в CI остаются обязательными, e2e-реестр покрывает только то, что
требует настоящей системы.

#### Scenario: Регрессия поведения установленной системы
- **WHEN** изменение ломает поведение, наблюдаемое только на установленной системе (раскладка пакета, PAM-фазы, обнаружение носителя, отзыв)
- **THEN** ближайший прогон `cargo xtask e2e` даёт расхождение с baseline и ненулевой код возврата

#### Scenario: Прогон перед релизом
- **WHEN** готовится выпуск релиза
- **THEN** реестр прогнан во всех доступных профилях, расхождения с baseline разобраны, стенд отработал без `ERROR`

### Requirement: Разграничение ручных проверок

Ручными ДОЛЖНЫ (MUST) оставаться только проверки, требующие вендорского железа
(JaCarta-2 GOST, Рутокен) и визуального контроля (выбор роли в fly-dm). Проверки первого
рода ДОЛЖНЫ (MUST) сохранять привязку к чек-листу релиза через runbook
`tests/scripts/install-and-test.sh`, пока в реестре не появятся кейсы с реальным токеном;
удаление runbook'а до этого момента ЗАПРЕЩЕНО (MUST NOT) — на него опираются
[ci-hardening](../../../ci-hardening/) и [gost-pkcs11](../../../gost-pkcs11/).

Проверки, ранее числившиеся ручными из-за отсутствия носителя (полный flow с USB,
vagrant E2E auth-flow), ДОЛЖНЫ (MUST) закрываться эмуляцией носителя в контейнерном
профиле реестра.

#### Scenario: Релиз с вендорским железом
- **WHEN** готовится выпуск релиза
- **THEN** пункт чек-листа о прогоне на JaCarta-2 GOST и Рутокен выполняется по runbook'у и остаётся обязательным

#### Scenario: Проверка USB-flow без железа
- **WHEN** нужно проверить полный flow с носителем вне релизного цикла
- **THEN** он прогоняется автоматически в контейнерном профиле на эмулированном носителе, а не вручную
