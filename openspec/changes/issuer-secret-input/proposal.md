## Why

`issuer` собирается и публикуется под Linux, macOS и Windows, а спека прямо требует
кроссплатформенности стороны выпуска. Но секрет — PIN токена и пароль ключа файлового
бэкенда — запрашивается только через `pinentry` (`cli.rs:1146`: probe `pinentry`,
`pinentry-mac`, `pinentry-gtk-2`, `pinentry-qt`, `pinentry-curses` на `PATH`), а при его
отсутствии остаётся единственный путь — переменные окружения `TESSERA_ISSUER_PIN` и
`TESSERA_ISSUER_KEY_PASSPHRASE`.

`pinentry` входит в состав GnuPG. На Linux он обычно есть, на macOS — только вместе с GPG Suite
или из пакетного менеджера, на Windows — только с Gpg4win. То есть на двух платформах из трёх
штатный сценарий сегодня — положить PIN токена в переменную окружения: в историю команд, в
окружение дочерних процессов, в дампы памяти и аварийные отчёты.

Требование кроссплатформенности выполнено формально (бинарь собирается), но не по существу
(инварианты обращения с секретом на двух платформах не сохраняются). Пока это так, любая
инструкция для стороны инженера — а `engineer-issuance-tooling` делает эту сторону массовой —
будет содержать худший из возможных советов.

Причина разрыва в том, что `pinentry` решает задачу, которой у нас нет: он существует, чтобы
`gpg-agent` мог запросить секрет, **не имея терминала**. `issuer` — интерактивный CLI, терминал
у него есть по определению.

## What Changes

- Вводится лестница источников секрета с явным приоритетом: явно заданный
  pinentry-совместимый диалог → найденный на `PATH` → **консольный ввод без эха** →
  `--pin-stdin` / `--pin-file` → переменная окружения.
- Консольный ввод без эха добавляется как основной интерактивный путь на всех платформах.
- Для автоматизации добавляются `--pin-stdin` и `--pin-file` (и симметричные для пароля ключа):
  оба безопаснее переменной окружения, которая видна в окружении дочерних процессов.
- Переменные окружения сохраняются как последнее средство и при использовании дают
  предупреждение в stderr.
- Поддержка стороннего pinentry остаётся: флаг `--pinentry` уже принимает любой
  Assuan-совместимый бинарь. Поставлять чужой pinentry в составе продукта не предполагается.

## Capabilities

### Modified Capabilities

- `issuer-signing`: требование к запросу секретов бэкендов получает явную лестницу источников;
  требование кроссплатформенности получает сценарий, проверяющий отсутствие `pinentry`.

## Impact

- Код: `crates/tessera_issuer/src/cli.rs` (модули `prompt`, `pin`, `keypass`), новые флаги в
  `BackendArgs`. Одна новая зависимость для отключения эха (крейт с готовым `unsafe` — в
  `tessera_issuer` действует `unsafe_code = "deny"`).
- Документация: инструкции перестают содержать совет о переменной окружения как штатный путь.
- Безопасность: секрет перестаёт попадать в окружение процесса в штатном сценарии на macOS и
  Windows.
- Не затрагивается: PIN-цикл агента на устройстве (там секрет приходит через PAM conversation) —
  это другой путь и другой change.
