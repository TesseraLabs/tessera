## Обнаружено при проверке фикса (вне объёма этого изменения)

- [x] 7. **Дефолты версии формата расходятся** — закрыто отдельным изменением, дефолт
  выпуска опущен до `0`; текущая версия формата зафиксирована в документации, ключ
  добавлен в `config.toml.example`.: `issuer` по умолчанию выпускает
  `profile_version = 1` (`cli.rs:172`), а Engine по умолчанию принимает максимум `0`
  (`DEFAULT_MAX_SUPPORTED_PROFILE_VERSION`, с пометкой «until the `[trust]` config key
  is wired through» — при том что ключ уже проводится). Спеки не фиксируют, какая версия
  текущая. Параметр `max_supported_profile_version` не документирован в
  `dist/config/config.toml.example`. Требуется решение: поднять дефолт Engine, опустить
  дефолт issuer или задокументировать обязательную настройку — отдельным изменением
- [x] 8. **Сквозной вход требует выбора роли** — разобрано и признано верным поведением.
  Копание вскрыло корень глубже: дело было не в рамках, а в миграционном ключе
  `[roles].enforce` с умолчанием «роли не проверяются», из-за которого роль не
  выбиралась вовсе. Ключ вырезан отдельным изменением (`roles-always-enforced`), вход
  требует роль безусловно; пер-хостовые цепочки перестают быть выпускаемым режимом
