# Наблюдение за присутствием токена

## Why

Сессия переживает извлечение токена. Демон следит за подсистемой блочных
устройств, а токен смарт-карты блочным устройством не является: `handle_udev`
выходит на первой же строке, когда носителем удостоверения выбран токен
(`crates/tessera_cli/src/state.rs:605`). Инженер вынимает токен и уходит —
экран остаётся разблокированным до истечения срока роли.

Это прямой экземпляр угрозы **T7** реестра (`docs/ru/threat-model.md` §10,
`high` / `likely`, `partially_mitigated`): «сессия переживает извлечение
носителя». Для съёмного носителя угроза частично закрыта — событие udev,
выдержка, действие. Для токена не закрыта вовсе, и `on_usb_removed` в
конфигурации выглядит настроенным, ничего при этом не делая.

Ограничение известно и до сих пор было приемлемым: `mode = "pkcs11"` живёт с
ним не первый год, а токен там — принадлежность узкого сценария. Изменение
`pkcs12-token-carrier` делает токен носителем удостоверения для обычного входа,
и защита начинает зависеть от того, в чём инженер принёс удостоверение, а не от
угрозы. Пока наблюдателя нет, `pkcs12-token-carrier` не отгружается.

Срок действия роли и PIN дыру не закрывают: они препятствуют новой
аутентификации, а не уже открытой сессии.

## What Changes

- Демон получает наблюдателя присутствия токена: периодический опрос
  PKCS#11 (`C_GetSlotList` + `C_GetTokenInfo`), сверка `serialNumber` с
  идентификатором носителя из реестра сессий.
- Пропажа токена подаётся в существующую машинерию: выдержка, отмена при
  возврате, настроенное действие. Новых действий не вводится.
- Устойчивый отказ самого опроса (умер `pcscd`, зависла библиотека)
  обрабатывается по режиму мониторинга: `strict` — как извлечение,
  `permissive` — деградация с записью в журнал.
- Запрет `strict` при источнике «токен» снимается: обещание непрерывного
  присутствия становится выполнимым.
- Контракт обнаружения переписывается честно: «не позже интервала опроса плюс
  выдержка». При нулевой выдержке интервал опроса и есть фактический минимум.

## Impact

- `crates/tessera_cli` — наблюдатель в демоне, конфигурация интервала.
- `crates/tessera_core/src/config` — ключ интервала опроса; снятие запрета
  `strict` при источнике «токен».
- `crates/pam_tessera/src/flow.rs` — снятие `ensure_pkcs11_presence_mode` для
  источника «токен».
- `docs/ru/carriers.md`, `docs/{ru,en}/configuration.md` — извлечение токена
  отслеживается; контракт обнаружения; поведение при отказе опроса.
- `docs/ru/threat-model.md` — T7 для токенного носителя.
- Затрагивает `mode = "pkcs11"` тем же наблюдателем: там дыра та же и
  закрывается тем же кодом.
