## MODIFIED Requirements

### Requirement: Источники

Источники в `[host_identity].sources` ДОЛЖНЫ (MUST) быть из допустимого набора: `device_number`
(номер устройства из подписанного device-манифеста enrollment-пакета), `machine_id`
(/etc/machine-id), `dmi_board_serial`, `dmi_system_uuid`, `dmi_system_serial` (sysfs DMI; алиасы
board_serial/system_uuid/system_serial), `hostname` (/etc/hostname), `custom_command` (внешняя
команда, timeout clamp 1..30s), `override` (фиксированное значение из `override`).

#### Scenario: custom_command с большим таймаутом
- **WHEN** `custom_command` задан с таймаутом вне диапазона 1..30s
- **THEN** значение clamp'ится в 1..30s

#### Scenario: device_number в списке источников
- **WHEN** `sources` содержит `device_number`
- **THEN** источник считается допустимым и разрешается цепочкой на общих правилах

## ADDED Requirements

### Requirement: Источник device_number

Источник `device_number` ДОЛЖЕН (MUST) отдавать номер устройства только при выполнении всех
условий: device-манифест enrollment-пакета присутствует, его подпись проверена доверенным
якорем, и `host_id_hash` из манифеста совпадает с идентичностью железа, вычисленной по
остальным источникам цепочки. Если хотя бы одно условие не выполнено — манифест отсутствует,
подпись невалидна, поле номера пусто или `host_id_hash` разошёлся — источник ДОЛЖЕН (MUST)
считаться пустым; отдавать номер без подтверждённой привязки к железу он НЕ ДОЛЖЕН (MUST NOT).
Пустой источник обрабатывается существующими правилами цепочки и fallback-политики; новых
кодов отказа не вводится.

#### Scenario: Манифест валиден и привязка совпала
- **WHEN** подпись манифеста проверена и `host_id_hash` совпал с идентичностью железа
- **THEN** источник отдаёт номер устройства как значение `host_id`

#### Scenario: Клон образа на другом железе
- **WHEN** манифест скопирован на другое устройство и `host_id_hash` не совпадает с его железом
- **THEN** источник пуст; при `fallback="deny"` аутентификация отклоняется

#### Scenario: Невалидная подпись манифеста
- **WHEN** подпись device-манифеста не проверяется доверенным якорем
- **THEN** источник пуст (fail-closed), номер не используется

### Requirement: Нормализация номера как host_id

К номеру, отданному источником `device_number`, ДОЛЖНА (MUST) применяться существующая
нормализация идентичности (trim, удаление `:` и пробелов, lowercase, затем SHA256) без
исключений. Следствие ДОЛЖНО (MUST) быть зафиксировано явно: номера, отличающиеся только
регистром букв, дают один и тот же `host_id_hash` и считаются одним устройством. Владелец
парка, чья нумерация различает регистр, использовать такие номера как разные НЕ ДОЛЖЕН
(MUST NOT).

#### Scenario: Номера, отличающиеся регистром
- **WHEN** на двух устройствах номера `04217a` и `04217A`
- **THEN** оба дают одинаковый `host_id_hash` — с точки зрения host-binding это одно устройство
