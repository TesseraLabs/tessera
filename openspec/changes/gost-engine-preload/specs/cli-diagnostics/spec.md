## MODIFIED Requirements

### Requirement: tessera check

Команда ДОЛЖНА (MUST) выполнять префлайт-валидацию БЕЗ запуска демона и без касания сокета: load config → startup-check pipeline (pam_stack ordering, mac runtime vs ядро, anchors, права CA-dir, parsec caps, host_identity probe, конфигурация ГОСТ). Вывод: строки `[INFO]/[WARN]/[ERROR]` в stdout + summary. Exit 0 ⟺ ноль ERROR; INFO/WARN на exit не влияют. Предназначен как `ExecStartPre=` hard-gate и валидатор в finish-bootstrap (check.rs:33–70).

**Шаг ГОСТ-конфигурации** ДОЛЖЕН (MUST) различать четыре состояния и
называть их устойчивыми идентификаторами:

| Запись | Уровень | Когда |
|---|---|---|
| `gost_engine_ok` | INFO | путь задан, ГОСТ-подпись разрешена allow-list'ом, engine готов |
| `pkcs11_openssl_unsupported` | ERROR | `mode = "pkcs11"` вместе с `crypto_backend = "openssl"` — аутентификация отвергается целиком, для любого удостоверения |
| `gost_engine_configured_unused` | WARN | путь задан, ГОСТ-подписи не разрешены, engine при этом готов — настройка выглядит забытой |
| `gost_engine_load_failed` | ERROR | путь задан, но engine не готов |

Запись о паре `mode`/`crypto_backend` НЕ ДОЛЖНА (MUST NOT) зависеть от
настроек ГОСТа: комбинация отвергает любое удостоверение, поэтому проверяется
она напрямую — и на хосте, где ГОСТ не разрешён и путь к движку не задан,
тоже. Прежнее имя записи (`gost_pkcs11_unsupported`) называло следствие вместо
причины и потому заменено.

Записи НЕ ДОЛЖНЫ (MUST NOT) вытеснять друг друга: если пара неверна И задан
путь к движку, в отчёт попадают обе. Порядок записей следует порядку отказов
в самопроверке — сначала движок, затем режим.

Успешная ГОСТ-конфигурация ДОЛЖНА (MUST) подтверждаться записью, а не
молчанием: оператору нужно видеть, что engine действительно загрузился, а не
что про него никто ничего не сказал.

Проверка ДОЛЖНА (MUST) выполнять ту же проверку готовности, которой
пользуется аутентификация, во ВСЕХ ветках, где заданный `gost_engine_path`
приводит аутентификацию к загрузке, — иначе префлайт расходится с реальным
поведением и перестаёт быть гейтом.

Проверка готовности ДОЛЖНА (MUST) быть единой функцией, а не совпадающей
парой вызовов: загрузка движка и резолюция обоих дайджестов
(`md_gost12_256`, `md_gost12_512`). Загрузка, принимающая альтернативные
имена дайджестов, недостаточна — она даёт INFO там, где аутентификация
откажет.

Наличие ГОСТ-OID в allow-list НЕ ДОЛЖНО (MUST NOT) быть условием загрузки:
движок нужен и без него — для ГОСТ-ключа в сертификате, подписанном другим
алгоритмом, и для контейнера, защищённого ГОСТ-PBE.

Хост, не использующий ГОСТ (путь не задан, ГОСТ-подписи не разрешены), НЕ
ДОЛЖЕН (MUST NOT) получать по этому шагу ни одной записи.

#### Scenario: Префлайт без ERROR
- **WHEN** `tessera check` отрабатывает pipeline и не получает ни одной ERROR-записи
- **THEN** команда печатает summary и завершается с exit 0 (INFO/WARN не влияют)

#### Scenario: Корректная ГОСТ-конфигурация подтверждается
- **WHEN** задан `gost_engine_path`, allow-list разрешает ГОСТ-подпись, engine загружается
- **THEN** печатается `[INFO ] gost_engine_ok`, exit 0

#### Scenario: Engine настроен, но недостижим
- **WHEN** `gost_engine_path` задан, ГОСТ-подпись разрешена, но engine не готов
- **THEN** печатается `[ERROR] gost_engine_load_failed` с причиной отказа, exit 1

#### Scenario: Engine недостижим, ГОСТ-подписи не разрешены
- **WHEN** `gost_engine_path` задан, ни одна ГОСТ-подпись не разрешена allow-list'ом, engine не готов
- **THEN** печатается `[ERROR] gost_engine_load_failed`, exit 1 — аутентификация грузит движок по самому факту заданного пути, поэтому на такой машине не войдёт никто

#### Scenario: Engine готов, но ГОСТ-подписи не разрешены
- **WHEN** `gost_engine_path` задан, ни одна ГОСТ-подпись не разрешена allow-list'ом, engine готов
- **THEN** печатается `[WARN ] gost_engine_configured_unused`, exit 0 — входу ничто не мешает, но настройка выглядит забытой после правки allow-list'а

#### Scenario: Токен вместе с OpenSSL-бэкендом
- **WHEN** `mode = "pkcs11"` и `crypto_backend = "openssl"`, ГОСТ не разрешён и `gost_engine_path` не задан
- **THEN** печатается `[ERROR] pkcs11_openssl_unsupported`, exit 1 — в этой комбинации аутентификация отвергает любое удостоверение, не только ГОСТ

#### Scenario: Неверная пара режима и бэкенда поверх настроенного ГОСТа
- **WHEN** `mode = "pkcs11"` и `crypto_backend = "openssl"`, при этом `gost_engine_path` задан и engine не готов
- **THEN** печатаются ОБЕ записи — `[ERROR] gost_engine_load_failed` и `[ERROR] pkcs11_openssl_unsupported`, exit 1: самопроверка при аутентификации проверяет движок раньше режима, и умолчание про движок развело бы префлайт с ней

#### Scenario: Хост без ГОСТ
- **WHEN** `gost_engine_path` не задан и ГОСТ-подписи не разрешены
- **THEN** по ГОСТ-шагу не печатается ни одной записи
