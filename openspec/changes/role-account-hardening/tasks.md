# Tasks: role-account-hardening

Решение принято: проверка по uid на входе (рубеж 1) + отказ грузить срез с
именем системной учётной записи (рубеж 2). Статический список зарезервированных
имён отвергнут: опасно не имя, а существующая в системе учётная запись с чужими
привилегиями; список расходился бы с дистрибутивом и отвергал законные роли.

- [x] 1. Вход: отказ, если учётная запись из `PAM_USER` системная (uid ниже границы обычных пользователей). Модуль уже делает `getpwnam` на этом пути (`flow.rs:1405`, резолв домашнего каталога) — новой зависимости не нужно
- [x] 2. Загрузка хранилища: срез с именем системной УЗ отвергается с внятной диагностикой; то же в `tessera-cli role lint`
- [x] 3. Границу «системная УЗ» задать одним местом с объяснением, откуда взято значение (1000 — `UID_MIN` в Debian/Ubuntu/Astra); не рассыпать константу по коду
- [x] 4. Тесты: вход в `root` отвергается даже при наличии среза и покрытии удостоверением; ролевая УЗ с uid из обычного диапазона проходит; срез `root.toml` не грузится
- [x] 5. Проверить, что отказ не даёт оракула: имя системной УЗ и её uid и так публичны через `getent`, но диагностика не должна сообщать о наличии/отсутствии среза
- [x] 6. `docs/{ru,en}/install.md`: закрыть остальные пути входа в ролевую УЗ явными командами (`passwd -l`, отсутствие `authorized_keys`, `AuthenticationMethods`, ограничение `su`). Census уже делает `passwd -l` при заведении — сверить и не противоречить
- [x] 7. `docs/{ru,en}/configuration.md`: гарантия «вход закрыт всеми путями» либо подпирается, либо снимается
- [ ] 8. Тест совместимости: лист с отозванным `pam_cert_user_binding` проходит проверку, расширение игнорируется как неизвестное non-critical
- [ ] 9. После (8) решить судьбу фикстур суффиксной модели (`tests/fixtures/roles/role-*.cnf`, `gen-role-certs.sh`, `vagrant/scripts/test-roles.sh`)
- [~] 10. Прогон e2e: добавить кейс на отказ входа в системную учётную запись
