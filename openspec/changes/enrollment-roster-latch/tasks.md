- [ ] 1.1 Формат наряда: список номеров, срок действия, идентификатор наряда; разбор и строгая валидация структуры

## 2. Ввод номера и защёлка

- [ ] 2.1 Команда персонализации: ввод номера, проверка формата и контрольного символа (валидатор из `device-number-identity`)
- [ ] 2.2 Проверка наличия номера в списке принятого наряда и живости срока действия
- [ ] 2.3 Атомарная запись привязки: номер, фактическая идентичность железа, идентификатор наряда; права ФС только для root

- [ ] 2.5 Тесты: опечатка, номер вне наряда, истёкший наряд, прерванная запись привязки

## 3. Однократность и жизненный цикл

- [ ] 3.1 Повторная защёлка на другой номер отвергается при существующей привязке
- [ ] 3.2 Повторная защёлка тем же номером при совпадающем железе — no-op
- [ ] 3.3 Снятие привязки в составе un-enroll (согласовать с change `device-lifecycle`)
- [ ] 3.4 Расхождение идентичности железа делает привязку недействительной без автоматической перезащёлки; причина пишется в лог
- [ ] 3.5 Тесты: перезащёлка на другой номер, идемпотентная повторная защёлка, un-enroll и последующая новая персонализация, перенос на другое железо

## 4. Источник device_number

- [ ] 4.1 Источник признаёт защёлкнутую привязку как второй носитель наравне с манифестом УЦ
- [ ] 4.2 Приоритет манифеста УЦ; расхождение номеров между носителями даёт пустой источник и запись в диагностический лог
- [ ] 4.3 Тесты: только защёлка, только манифест, оба совпадают, оба расходятся
