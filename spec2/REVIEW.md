# Ревью инструмента spec2/tools

Дата: 2026-08-30. Предмет: весь код в `spec2/tools/` (Node ESM, без внешних зависимостей).
Контракт, против которого читалось: `spec2/constitution.md` и `spec2/profile.yaml`.

Пометка **проверено** означает, что отказ воспроизведён запуском кода, а не выведен чтением.
Тег **[codex]** — находка независимой кросс-читки Codex, подтверждённая мной запуском.
Тег **[both]** — найдено обоими независимо.

Правки не вносились: это список, а не диффы.

## Итог

**Ложная зелёность подтверждена в семи независимых местах.** Инструмент сейчас может пройти
`lint` с кодом 0 на файле, где evidence взят из иллюстрации в блоке кода, обязательные якоря
вида не проверялись вовсе, применённый паттерн проигнорирован, а запрет `MUST NOT` прочитан как
обязательство `MUST`. 113 зелёных тестов этого не ловят, потому что покрывают happy path каждого
разборщика, а не случай «разбор не удался».

Находок: **CRITICAL 7, HIGH 5, MEDIUM 23, LOW 13** — всего 48.

О кросс-читке Codex: запускалась дважды. Первый прогон упал с `EPERM` на журнале задания под

# CRITICAL — проверка молча не проверяет

## C1. Evidence, Outcomes, Partition и Combinations извлекаются из СЫРОГО тела, минуя `maskZones`

`parse.mjs:366` (`extractConformance(bodyLines, …)`), `parse.mjs:370-378` (цикл сбора Evidence),
`parse.mjs:384` (`extractOutcomesAndPartitions`), `parse.mjs:385` (`parseCombinations`).

Заголовки, ссылки и нормы читаются из `masked` (`parse.mjs:356-365`), а эти четыре — из
`bodyLines`. Конституция §9 требует обратного: вкопированных фрагментов кода в spec2 не бывает,
и иллюстрация не имеет притязания на смысл.

**Сценарий отказа, проверено.** Требование без единого настоящего Evidence, но с иллюстрацией
внутри своей секции:

````markdown
### Requirement: Настоящее {#AUTH-903 kind=инвариант}

[[сущность:probe2]] MUST работать.

Пример того, как НЕ надо (иллюстрация):

```markdown
**Evidence:** `test:tools/spec.mjs#lint`
**Outcomes:** `а` | `б` (закрыто)
```
````

`E-EVIDENCE-MISSING` для AUTH-903 **не выдаётся**: якорь из примера засчитан как настоящий и
даже отправлен на резольв. То же произойдёт с `**Outcomes:**` и с таблицей комбинаций внутри
фенса.

**Лечение:** передать `maskedLines` вместо `bodyLines` в четыре вызова. Самая дешёвая правка
в отчёте относительно последствий.

## C2. `profile.yaml` объявляет контракт, который линт почти не реализует

Проверено грепом по всем `tools/*.mjs` и прогоном на фикстурах.

- **`kinds.<вид>.anchors.required`** читается только в `checkEntityTypeAnchor` (`lint.mjs:340`)
  и только ради значения `type` (`lint.mjs:344`: `if (!required.includes('type')) continue;`).
  `операция: anchors.required: [code, test]`, `паттерн: [exemplar]`, `событие: [test]`,
  `политика: [test]` **не проверяются ничем**.
  *Проверено:* файл с `kind: операция` вообще без секции `anchors:` во frontmatter — ноль
  находок линта.
- **`kinds.событие.must: [producer]`** и **`kinds.решение.must: [rejected_alternative]`** —
  строка `must` сверяется только с литералом `'outcomes'` (`lint.mjs:575`). Событие без
  источника проходит. `checkDecisionAlternative` (`lint.mjs:473`) хардкодит имя секции
  «Отвергнутые альтернативы» вместо чтения `must`.
- **`kinds.<вид>.links.may_reference`** — **не читается нигде** (0 вхождений в коде). Ссылка
  `политика → паттерн`, запрещённая профилем, проходит молча. Это центральное обещание
  профиля: конституция §9 определяет вид термина через «собственные легальные связи».
- **`kinds.решение.lifecycle: [принято, отменено, заменено]`** — не читается (0 вхождений).
  Поле `superseded_by` из конституции §7 тоже нигде не проверяется.

Опасность не в отсутствующих проверках самих по себе, а в том, что профиль читается человеком
как описание того, что проверяется. Полный список того, что профиль обещает впустую, — в
отдельном разделе «Профиль обещает — код не читает» ниже.

**Лечение:** либо реализовать эти ключи, либо явно помечать нереализованные ключи профиля
находкой при загрузке, чтобы профиль не врал.

## C4. Свой YAML молча обрезает документ [both]

`yaml.mjs:260-265` — `parseYAML` выбрасывает возвращённый `parseNode` курсор и никогда не
проверяет, что все строки потреблены. `yaml.mjs:231` — `parseMapping`: `if (!m) { i++; continue; }`,
нераспознанная строка пропускается молча. `yaml.mjs:250` — цикл выходит при первом же
несовпадении отступа, весь остаток документа теряется.

**Сценарий 1, проверено — блочный скаляр.**

```
id: foo
descr: |          →  {"id":"foo","descr":"|"}
  line one
  line two
kind: сущность
context: auth
```

`kind`, `context` и всё, что ниже, исчезли, а `parseFrontmatter` вернул `error: null`.
Блочные скаляры не поддерживаются сознательно (`yaml.mjs:3-4`) — но неподдержка обязана быть
ошибкой, а не тихой обрезкой.

**Почему это ложная зелёность, а не громкая ошибка.** Если `description: |` стоит ПОСЛЕ
`id/kind/context` (обычный порядок полей), файл остаётся формально валидным: `hasValidFrontmatter`
(`lint.mjs:72`) истинно, `E-FRONTMATTER` не выдаётся, — а `anchors:` и `applies:`, стоящие ниже,
пропадают. Все якорные и паттерновые проверки для этого файла молча не выполняются.

**Сценарий 2, проверено — сбитый отступ одной строки.**

```
id: foo
anchors:
  - code:a.rs#x
 stray: 1          ← отступ 1
kind: сущность     ← НИКОГДА не разбирается
                   →  {"id":"foo","anchors":[{"code":"a.rs#x"}]}
```

**Сценарий 3, проверено — дубли ключей.** `k: 1\nk: 2` → `{"k":2}`, last-wins без предупреждения.
Если терм объявит `anchors:` дважды, один блок исчезнет бесследно.

**Сценарий 4, проверено — незакрытая flow-коллекция.** `b: {x: 1` без `}` → `{"b":{"x":1}}`,
ошибки нет (`yaml.mjs:127-129`: цикл выходит по `break`, когда не встретил ни `,`, ни `}`).

**Лечение:** `parseYAML` обязан бросать на непотреблённых строках, на блочных скалярах (`|`, `>`),
на дублях ключей и на незакрытой flow-коллекции. Это чинит заодно M14 и большую часть риска по M4.

## C5. Rust-адаптер теряет `panic!`/`unwrap` через раз

`adapters/rust.mjs:151-157` — `ESCAPE_PATTERNS` объявлены на уровне модуля с флагом `/g`.
`adapters/rust.mjs:168` — `re.test(body)` без сброса `lastIndex`. Глобальный regex сохраняет
позицию между вызовами.

**Проверено**, три вызова подряд на одном и том же источнике `fn a() -> u8 { panic!(); 0 }`:

```

call2 []
call3 ["panic!"]

TS- и C#-адаптеры сбрасывают `lastIndex` корректно (`typescript.mjs:205,213,289`,
`csharp.mjs:163,176,178,291`), `candidates-cmd.mjs:210,221,230` тоже. Баг только в rust.mjs.

## C6. TS-адаптер выдаёт `confidence: "exact"` по закомментированному объявлению [codex]

`adapters/typescript.mjs:225-227` — поиск объявлений идёт по сырому `source`, хотя `blankNonCode`
(`adapters/shared.mjs:141`) существует ровно для этого и уже используется C#-адаптером
(`csharp.mjs:290`).

**Проверено:**

```js
extractOutcomes('// enum Status { Fake }\nexport enum Status { Real }', 'Status')
→ {declared:["Fake"], escaping:[], confidence:"exact", unresolved:[]}
```

Настоящий enum не виден вовсе. `exact` — самое сильное утверждение, которое инструмент умеет
делать о коде, и здесь оно ложно, причём без единой записи в `unresolved`.

**Лечение:** прогонять поиск объявлений через `blankNonCode(source)`, как это уже сделано в C#.

## C7. TS-адаптер теряет `throw` без завершающей точки с запятой [codex]

`adapters/typescript.mjs:187` — `const THROW_STMT_RE = /\bthrow\s+([\s\S]*?);/g` требует `;`.
ASI (автоматическая вставка точки с запятой) — легальный TypeScript.

**Проверено:**

```js
'export function f(): number {\n  throw new Error("boom")\n}\n'
→ escaping: [], unresolved: ["union-член \"number\" не разобран…"]   ← про throw НИ СЛОВА
```

Задание требовало, чтобы неразобранное попадало в `unresolved`; здесь оно исчезает бесследно.

**Важное уточнение для исполнителя.** Отказ не детерминирован по форме самого `throw`, а
зависит от остального тела функции. Проверено: `{ if (x) { throw new Error("boom") }\n return 1; }`
throw **ловит** — за счёт чужой `;` от `return 1;`, при этом в `escaping` попадает выражение,
растянутое через закрывающую скобку. Регрессионный тест нужно писать на тело, где после `throw`
точки с запятой нет вообще, иначе тест пройдёт на сломанном коде.

# HIGH

## H1. `MUST NOT`, перенесённый на новую строку, читается как `MUST`

`markdown.mjs:145` — `const OPERATOR_RE = /\bMUST NOT\b|\bMUST\b|\bMAY\b/g` требует ровно один
пробел между словами.

**Проверено:**

```js
findOperators('Клиент MUST\nNOT делать это.')   → [{op:"MUST", index:7}]
findOperators('Клиент MUST  NOT делать это.')   → [{op:"MUST", index:7}]
```

Запрет становится обязательством. Семантика нормы инвертируется, и инверсия уходит дальше по
конвейеру: в `analyzeNorms` (`parse.mjs:226`), в граф (`graph.mjs:230`) и в срезы. Текст
предложения склеивается через `\n` (`parse.mjs:219`), поэтому перенос строки внутри предложения —
норма, а не исключение; в `constitution.md` строки уже переносятся по ~80 колонок.

**Лечение:** `/\bMUST\s+NOT\b|\bMUST\b|\bMAY\b/`. Две минуты.

## H2. Элемент `applies:`, не являющийся объектом, молча игнорируется

`lint.mjs:392` — `if (!app || !app.pattern) continue;`. То же в `graph.mjs:167`
(`computeObligations`) и `graph.mjs:271` (`buildGraph`).

**Проверено**, файл с двумя записями:

```yaml
applies:
  - fail-closed              # ← НИ ОДНОЙ находки
  - pattern: strict-parse    # ← E-PATTERN-VERSION выдан корректно
```

Вывод линта: только `E-PATTERN-VERSION — паттерн "strict-parse@undefined" не существует`.
Про первую запись — тишина.

Первая форма — правдоподобная ошибка автора (список имён вместо списка объектов). Последствия:
паттерн не применяется, обязательства не вычисляются, `E-PATTERN-OBLIGATION-NO-EVIDENCE`
не срабатывает, ребро `применённый-паттерн` в граф не попадает.

**Лечение:** находка `E-PATTERN-MALFORMED` вместо `continue`.

## H3. Вырожденная таблица комбинаций объявляется полной

Два независимых пути, оба ведут к «нарушений нет».

**Путь А — измерение с пустым списком значений.** `combinations.mjs:149-156` (`cartesianProduct`):
внутренний цикл по `dim.values` не выполняется ни разу, `next` остаётся пустым, `result`
становится `[]`.

*Проверено:*

```js
analyzeCoverage({dims:[{name:'a',values:['x','y']},{name:'b',values:[]}], rows:[…]})
→ {uncovered:[], overlaps:[]}
```

Ноль сочетаний → ноль непокрытых → «таблица полна и непересекается», хотя не проверено ничего.
`splitDimValues` (`combinations.mjs:33`) отфильтровывает пустые строки, так что до пустого списка
добраться нетрудно.

**Путь Б — ноль распознанных измерений.** `lint.mjs:700` —
`if (table.dims.length === 0 || table.rows.length === 0) continue;`. Раздел `## Combinations`
присутствует, таблица со всеми строками присутствует, а проверка полноты молча не запускается,
и об этом не сообщается ни строкой. Дойти до нуля измерений просто: `DIM_RE`
(`combinations.mjs:12`) требует именно длинное тире U+2014 (`—`). Короткое тире `–`, дефис `-`
или перенос значений на следующую строку (`(.+)$` требует хотя бы один символ после тире)
выбивают строку измерения целиком.

**Дополнительно: число колонок таблицы с числом измерений не сверяется нигде.**
`combinations.mjs:122` — `cells.slice(1, 1 + dims.length)`, `:123` — `cells[1 + dims.length]`.
Потерянное измерение сдвигает все ячейки. Здесь ошибка выходит громкой (столбец исхода без
бэктиков → `outcome === null` → `E-COMBINATIONS-UNKNOWN-OUTCOME` на каждую строку), но
полагаться на это не стоит.

**Лечение:** диагностика «раздел Combinations есть, измерений распознано ноль»; отказ на
измерении с пустым списком значений; проверка `cells.length === dims.length + 2` для каждой
строки данных.

## H4. Покрытие исходов и классов сценариями проверяется подстрокой

`lint.mjs:625` (`checkOutcomesScenarioCoverage`) и `lint.mjs:660` (`checkPartitions`) — оба
используют `combined.includes(v)`.

**Проверено:**

```markdown
**Outcomes:** `отозвано` | `не отозвано` (закрыто)

#### Scenario: единственный

Проверяем, что результат — `не отозвано`.
```

Ни одного `W-OUTCOMES-NO-SCENARIO`, потому что `"не отозвано".includes("отозвано")` истинно.
Исход `отозвано` не покрыт ни одним сценарием, и инструмент об этом молчит.

В домене, где половина исходов — отрицания другой половины (а `auth` именно такой:
отозвано/не отозвано, доступен/недоступен, свежа/устарела), проверка систематически ложно
проходит ровно на той паре, ради которой писалась.

**Лечение:** сравнение по границам токена, а не подстрокой.

## H5. Резольв evidence-якоря — подстрока по всему файлу [both]

`graph.mjs:140` — `content.includes(anchor.symbol)`.

Конституция §5 честно объявляет это проверкой битой ссылки, а не семантической синхронности,
и претензий к замыслу нет. Претензия в том, что заявленный уровень не достигается даже для
битой ссылки: символ, оставшийся в комментарии, в строковом литерале, в тесте или внутри
другого идентификатора (`check_revocation_disabled`), держит якорь «разрешённым» после удаления
самой функции. Для коротких символов (`new`, `get`, `run`, `id`) проверка вырождается в
тождественную истину.

**Побочно, там же:** `fs.existsSync` (`graph.mjs:132`) истинен для директории, так что
`code:crates/` разрешается; `path.join(root, anchor.file)` (`graph.mjs:131`) не ограничен корнем,
так что якорь с `../../..` резольвится наружу репозитория и читается оттуда.

# MEDIUM

## M1. `maskZones` слишком груба [codex]

`markdown.mjs:13-32`. Переключатель фенса (`:18`, `/^(```+|~~~+)/`) не помнит ни тип маркера,
ни его длину: строка из трёх бэктиков внутри блока из четырёх закрывает его, и остаток файла
выходит из-под маски со всеми нормами и ссылками. Не маскируются: код с отступом в четыре
пробела, ленивые продолжения цитаты (строка без `>` внутри блока цитаты), инлайн-код с двойными
бэктиками, инлайн-код через перенос строки. Непарный бэктик в строке (`:31`,
`/`[^`]*`/g`) оставляет её целиком видимой.

Направление отказа здесь в обе стороны: недомаскировка даёт ложные срабатывания, а фенс,
закрытый раньше времени (или, наоборот, открытый), прячет настоящие нормы.

## M2. Русские операторы ловятся не все [both]

`markdown.mjs:165`. Список закрыт перечислением: `ЗАПРЕЩАЕТСЯ`, `ЗАПРЕЩЁН`, `НЕЛЬЗЯ`, `МОГУТ`,
`МОЖНО`, `SHALL`, `REQUIRED`, `SHOULD NOT` не ловятся.

*Проверено:* `findRuOperators(['ЗАПРЕЩАЕТСЯ это','НЕЛЬЗЯ то','МОГУТ сделать'], 1)` → `[]`.

Класс границы `[A-Za-zА-Яа-яЁё]` не включает цифры, подчёркивание и комбинирующие знаки;
нормализации к NFC нет, поэтому декомпозированные `й`/`ё` проходят мимо и лукахеда, и самого
списка.

Ограничение верхним регистром я считаю оправданным (конституция §1 пишет операторы капслоком,

## M7. Бюджет среза считает не файлы, seed списывает бюджет впустую [codex]

`slice.mjs:112` — `budget.tryLoad(\`${found.file.path}#${node.id}\`)`, при заявленном в

--- за границей бюджета (budget.max_files=1), деградировано до имён ---

- gamma
```

Срез, обещающий «не обрезать молча, а деградировать», вернул только список из двух одинаковых

## M8. Циклы и параллельные рёбра дублируют вывод в обход бюджета

`slice.mjs:203` вызывает `renderNode` на каждое ребро, а `Budget.tryLoad` (`slice.mjs:64-68`)

разных типов между одной парой узлов проходят оба. Дедупликации `blocks` нет.

**Проверено:** файл `terms/c.md`, где один и тот же терм упомянут и в прозе (ребро `ссылка`),

На реальном графе, где термы обычно и упоминаются, и являются субъектами, это систематическое
удвоение среза, который существует ради экономии контекста.

## M9. Производительность обхода квадратична

`slice.mjs:15` (`findNode` — линейный скан всех узлов), `slice.mjs:25` (`findRequirement` —

На 500+ файлах станет заметно. Лечение — два `Map` по id, построенных один раз в `buildGraph`;
правка на десяток строк.

## M10. `cartesianProduct` не ограничен ничем [both]

`combinations.mjs:149`. Сейчас 192 сочетания, и это безобидно. Восемь измерений по пять значений —

## M11. Коллизии id между контекстами

## M12. Границы предложений — только точка

`markdown.mjs:129`. `!`, `?` и многоточие предложение не завершают: две нормы сливаются в одну,
и ссылка из первой становится «субъектом» оператора из второй, гася `E-NORM-NO-SUBJECT`.

без ссылки даёт ложное `E-NORM-NO-SUBJECT`.

## M13. Субъектом считается любая ссылка перед оператором

`lint.mjs:207` через `parse.mjs:234` (`linkMatches.filter(l => l.index < o.index).pop()`).
Вид ссылки не проверяется. `[[решение:ADR-002]] … MUST …` проходит как норма с субъектом,
хотя решение субъектом нормы быть не может. Проверки против `kinds.<вид>.links.may_reference`
тут нет — см. C2.

## M14. `#` внутри строки с апострофом не отрезается

`yaml.mjs:20`. *Проверено:* `title: don't do it # comment` → значение `don't do it # comment`.
Одиночная кавычка в неквотированном скаляре переключает `inSingle` (`yaml.mjs:16`), и всё,
что дальше, считается «внутри строки». То же при нечётном числе двойных кавычек в строке.

## M15. Имя символа подставляется в RegExp без экранирования

`adapters/rust.mjs:195` — `new RegExp(\`fn\\s+${symbol}\\s*(?:<[^>]*>)?\\s*\\(\`)`.
`adapters/typescript.mjs:145-148` — три паттерна подряд.

Якорь с `(`, `+`, `[`, `*` в символе даёт либо `SyntaxError` и падение `spec.mjs outcomes`
без обработки, либо тихое несовпадение.

**Там же, `typescript.mjs:148`:** третий паттерн
`(?:public\s+|private\s+|protected\s+|static\s+|async\s+|readonly\s+)*${symbol}\s*(?:<[^(]*>)?\s*\(`
совпадает с любым ВЫЗОВОМ функции, а не только с объявлением, — адаптер может уехать в чужие
фигурные скобки и выдать уверенный неверный результат.

## M16. Строки `**НЕ ОПРЕДЕЛЕНО**` участвуют в проверке полноты [codex]

`lint.mjs:684-689` исключает такие строки из проверки имени исхода (`continue`), но
`analyzeCoverage(table)` на `lint.mjs:702` работает по всем `table.rows`, включая их.
Задокументированная дыра засчитывается как покрытие.

На REV-002 это ровно те шестнадцать сочетаний, которые я пересчитал независимо (см. ниже).

Возможно, так и задумано — дыра ведь объявлена, — но тогда это стоит сказать в тексте находки:
сейчас `E-COMBINATIONS-NOT-TOTAL` и `W-COMBINATIONS-UNDEFINED-ROW` читаются как два независимых
сигнала, а на деле второй гасит первый. **Решение за владельцем спеки, это вопрос замысла,
а не баг.**

Рекомендация Codex («treat undefined rows as uncovered when require_total is enabled») мной
не поддерживается: это превратит `E-COMBINATIONS-NOT-TOTAL` в постоянную ошибку на файле,
который всё делает правильно. Достаточно, чтобы сообщение о полноте называло число сочетаний,
покрытых только строкой `НЕ ОПРЕДЕЛЕНО`.

## M17. `spec.mjs outcomes` не видит якоря frontmatter

`outcomes-cmd.mjs:56` берёт только `req.evidenceAnchors`. Профиль требует `code:` именно во

по профилю, команда скажет «у требования нет code:-якоря с символом — сверять нечего» и выйдет
с нулём.

# Ответы на два отдельных вопроса

## 1. Таблица REV-002 — проверял независимо, утверждение подтвердилось

```
всего сочетаний: 192
НЕ ПОКРЫТО (считая строку 17): 0
ПЕРЕСЕЧЕНИЙ (считая строку 17): 0
покрыто ТОЛЬКО строкой 17: 16

## 2. `slice.mjs` — завершаемость да, деградация нет

**Завершаемость подтверждена** — и рассуждением, и запуском. Обход `обратные`

*Проверено* на фикстуре с циклом `alpha ↔ beta` и срезом `why` (`обратные`, `hops: 2`,
`load: full`): команда отработала, вернула оба файла, `EXIT=0`, зависания нет.

**Деградация до имён не работает как заявлено** — четыре отдельные проблемы, все проверены
запуском, подробности в M7 и M8:

1. `budget.on_exhaustion` не читается нигде — поведение при исчерпании захардкожено.

Плюс отдельно: цикл и параллельные рёбра дублируют полный вывод узла в обход бюджета (M8).
